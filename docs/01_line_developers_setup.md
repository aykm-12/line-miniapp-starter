# 1. LINE Developersの設定

## 1-1. プロバイダーの作成

1. [LINE Developers Console](https://developers.line.biz/console/) にLINEアカウントでログイン
2. 「新規プロバイダー作成」からプロバイダーを作成（会社名やチーム名など、任意の名前でOK）

## 1-2. LINEミニアプリチャネルの作成

1. プロバイダーを選択した状態で「チャネル設定」→「新規チャネル作成」→「LINEミニアプリ」を選択
2. 必須項目を入力
   - **サービスを提供する地域**（日本 / タイ / 台湾）
   - **チャネル名**（「LINE」またはそれに類する文字列は使用不可）・チャネル説明・メールアドレス（後で編集も可能）
3. 「LINE開発者契約」「LINEミニアプリプラットフォーム規約」「LINEミニアプリポリシー」に同意し、「作成」をクリック
4. 情報利用に関する同意画面で「同意する」をクリックすると、チャネルが「未認証ミニアプリ」として作成される

> 作成したLINEミニアプリチャネルは、コンソール上は1つに見えますが、内部的には**開発用・審査用・本番用**の3つの内部チャネルで構成されています。開発中は「開発用」の内部チャネルを使います。詳細は[LINEミニアプリ用LINE Developersコンソールガイド](https://developers.line.biz/ja/docs/line-mini-app/discover/console-guide/)を参照してください。

## 1-3. LIFF IDとエンドポイントURLの設定

各内部チャネルには、あらかじめLIFFアプリ（LINEミニアプリ本体）が1つずつ自動で追加されています。新規にLIFFアプリを追加することはできません。

このスターターでは、開発段階から**本番用**の内部チャネルをそのまま使う構成にしています。Vercelの本番デプロイURL（`https://xxxx.vercel.app` など）はpushのたびに変わらないため、最初から本番用のエンドポイントURLに設定しておけば、後からURLを差し替える手間がありません。

1. 作成したチャネルの「ウェブアプリ設定」タブを開く
2. 「本番用」の項目で **LIFF ID**（`1234567890-AbCdEfGh` のような形式、LIFF URLの/以降）を確認してメモしておく
3. 「エンドポイントURL」は、いったん仮のURLが入っている。Vercelへのデプロイ後にURLを更新する手順は[docs/03_vercel_deploy.md](03_vercel_deploy.md)を参照してください

> LINEミニアプリのLIFFアプリは、プロフィール情報（`profile` スコープ）へのアクセスがあらかじめ組み込まれており、通常のLIFFアプリのようにScopeやサイズ、ボットリンク機能を個別に変更することはできません。ただし `chat_message.write` スコープ（トークルームへのメッセージ送信）は例外的に個別有効化が可能です。詳しくは[docs/06](06_liff_advanced_features.md#通知機能sendmessages--sharetargetpickerを使うには)を参照してください。

### ⚠️ 本番用チャネルを開発から使う場合の注意点

- **未認証ミニアプリの間は「開発用」の設定変更がそのまま「本番用」にも反映されます。** そのため審査を申請するまでは、開発用と本番用を分けて使う意味はほとんどありません。ただし本番用チャネルは常に一般公開されている状態なので、開発途中の未完成な画面やエラーも、URLを知っている人には見えてしまいます。
- **本番用のエンドポイントURLにはベーシック認証をかけられません。** ベーシック認証が指定できるのは「開発用」「審査用」のエンドポイントURLのみです。そのため本番用チャネルを使う場合、Vercel側のベーシック認証で保護することはできず、URLを知っている人には誰でもアクセスできてしまう点に注意してください。人に見られたくない実装を試す場合は、一時的に「開発用」チャネル（Vercelのプレビューデプロイなど）に切り替えて作業することを検討してください。
- **審査を申請すると挙動が変わります。** 審査（認証済みミニアプリ化）を申請すると、それ以降は「開発用」の変更が自動では「審査用」「本番用」に反映されなくなり、審査開始時・公開時にそれぞれ明示的に設定がコピーされる方式に切り替わります。つまり今回の「最初から本番用を使う」構成は、あくまで審査申請前の開発フェーズ向けの簡易構成です。審査を申請する段階になったら、改めて開発用・審査用・本番用の使い分けを見直してください。

## 1-4. .env への設定

`.env` は `.gitignore` に含まれておりGitHubには含まれていないため、リポジトリをクローンした後に自分で作成する必要があります。リポジトリ直下の `.env.example` をコピーして `.env` を作成し、`VITE_LIFF_ID` にメモしたLIFF IDを設定してください。

```bash
cp .env.example .env
```
### Windowsの場合
```bash
Copy-Item .env.example .env
```
### 自身のIDを.envに記載
```
VITE_LIFF_ID=1234567890-AbCdEfGh
```

（`VITE_SUPABASE_URL` / `VITE_SUPABASE_PUBLISHABLE_KEY` は [docs/02_supabase_setup.md](02_supabase_setup.md) を参照して設定します）

## 1-5. 動作確認について

- **`npm run dev` でローカル起動し、PCブラウザで開いて確認するのが基本的な開発方法です。** ローカル開発中はLINEアプリの外（PCブラウザ）からでも動作確認でき、`liff.login()` がブラウザのLINEログイン画面にリダイレクトします。
- 実機のLINEアプリで正しく開くには、後述のVercelデプロイ後に「エンドポイントURL」を実際のデプロイURLに更新する必要があります。
- **デプロイ後は、VercelのURL（LIFF URLも含む）はLINEアプリ上でしか正常に開けません。** LINEアプリ以外の通常ブラウザで直接開くと、自動的にLINEアプリへリダイレクトされます（ローカル開発中は除く）。
